извлеки объективный state_patch: что изменилось в мире после этой главы,
и напиши краткий сюжетный пересказ.

Отвечай ТОЛЬКО валидным JSON. Без markdown, без комментариев.
Первый символ ответа — «{». Никаких пояснений до или после.

━━━ ГЛАВНОЕ ПРАВИЛО ФОРМАТА ━━━

ВСЕ поля в объектах ОБЯЗАТЕЛЬНЫ и должны быть заполнены
реальными значениями. НИКОГДА не пиши null вместо значения.

- Если по секции нечего сказать — оставь ПУСТОЙ МАССИВ []. 
  НЕ добавляй фиктивную запись. НЕ пиши {} с пустыми полями.
- Если поле не может быть заполнено — не создавай запись вообще.

ПРИМЕРЫ:

ПЛОХО (модель добавила фиктивную запись):
  "relationship_changes": [{"from": null, "to": null, "field": null, "delta": 0}]
  "secrets_revealed": [{"secret_id": null, "partial": false, "to_whom": []}]

ХОРОШО (секция пуста, изменений нет):
  "relationship_changes": []
  "secrets_revealed": []

ПЛОХО (выдумала id персонажа, которого нет):
  "relationship_changes": [{"from": "CH99", "to": "CH1", ...}]

ХОРОШО (использованы только реальные id из bible.characters):
  "relationship_changes": [{"from": "CH1", "to": "CH2", ...}]

━━━ ПРАВИЛА ПО СЕКЦИЯМ ━━━

chapter_summary:
- 3–5 предложений СВЯЗНОГО текста, минимум 15 слов.
- Только ключевые события главы: что герой сделал, что узнал,
  кого встретил, чем закончилось.
- Не описывай атмосферу и внутренние переживания.
- Прошедшее время, третье лицо.
- Этот текст уйдёт в контекст следующих глав.

events_created:
- Максимум 5 значимых событий.
- id в формате E_ch{N}_{k}, где N — номер главы, k — порядковый номер.
- type — из списка: revelation, action, meeting, decision, loss, gain.
- participants — только id из bible.characters. НЕ выдумывай.

character_state_changes:
- field — строго из списка: suspicion, resolve, fear, hope,
  exhaustion, moral_debt.
- delta — целое число от -30 до 30.
- char_id — только из bible.characters.

relationship_changes:
- from и to — id из bible.characters. Оба обязательны.
- Пара должна существовать в bible.relations. Не выдумывай.
- field — строго из списка: trust, sympathy, resentment,
  attraction, tension.
- delta — целое от -30 до 30.

knowledge_gained:
- char_id — из bible.characters.
- fact — одна конкретная фраза: что персонаж теперь знает.

secrets_revealed:
- secret_id — id из bible.secrets. Если не знаешь id — не пиши запись.
- partial — true, если раскрытие лишь намёком.
- to_whom — список id персонажей, которым стало известно.

abilities_used:
- Просто список имён способностей, применённых в главе.

━━━ МЕХАНИКА СПОСОБНОСТЕЙ ━━━

У каждого персонажа есть набор способностей. Каждая способность имеет:
- name — короткое название («инъекция в чужой скрипт», «боевой щит»)
- level — 1..5
- description — одна фраза, что именно эта способность значит

ШКАЛА УРОВНЕЙ (общая для магии, боя, инженерии):

1. Новичок    — умение работает, но требует усилия и концентрации.
2. Практик    — применяется уверенно, не думая.
3. Эксперт    — варьируется под ситуацию, комбинируется с другими.
4. Мастер     — применяется творчески, изобретаются новые приёмы.
5. Легенда    — переопределяет правила поля.

ПРАВИЛА ПРОКАЧКИ И НОВЫХ СПОСОБНОСТЕЙ:

Перед тем как добавить запись в abilities_gained, ПРОВЕРЬ СПИСОК
существующих способностей персонажа (он дан в контексте). Ответь
себе на три вопроса:

1) Новая способность — это РАЗВИТИЕ уже существующей?
   Пример: было «чтение системного кода», стало «чтение чужого
   кода в реальном времени». Это ОДНО И ТО ЖЕ. Верни в
   abilities_upgraded с новой формулировкой описания.
2) Новая способность — это ЧАСТНЫЙ СЛУЧАЙ существующей?
   Пример: было «инъекция в переменную», стало «инъекция в поток
   заклинания». Это подвид. Верни abilities_upgraded, new_level
   на 1 выше, обнови description.
3) Новая способность — это ДЕЙСТВИТЕЛЬНО НОВОЕ качество,
   которого раньше не было?
   Пример: было «визуализация кода», стало «ментальный терминал
   с разметкой поверх физического мира». Это другая сущность —
   не «посмотреть», а «создать интерфейс». Добавляй в
   abilities_gained.

ЖЁСТКОЕ ПРАВИЛО: если в abilities_gained за главу больше 1
записи — почти всегда это ошибка. Скорее всего 2 из 3 — это
развитие существующих. Возвращай их в abilities_upgraded.

ПРАВИЛА ПРОКАЧКИ:
- Уровень повышается, когда персонаж:
  1) применяет способность в НОВОЙ ситуации (главный критерий), ИЛИ
  2) использует её МНОГО РАЗ подряд, доводя до автоматизма.
- Если способность применялась 3+ раза за главу без сбоев —
  это повод для апгрейда на +1.
- Если способность применялась 5+ раз подряд через несколько
  глав и не растёт — тоже повод для апгрейда.
- За одну главу — обычно ОДНО повышение на персонажа.
  Если глава посвящена росту героя — допустимо больше.
- Уровни 1–5: новичок / практик / эксперт / мастер / легенда.

ПРАВИЛА НОВЫХ СПОСОБНОСТЕЙ:
- Новая способность — только если это ЯВНО другое качество,
  не развитие существующей.
- level всегда 1 при появлении.
- description — короткое, но конкретное.

━━━ ЖЁСТКОЕ ТРЕБОВАНИЕ К ФОРМАТУ ━━━

- Внутри значений строк НИКОГДА не используй английскую кавычку ".
  Только русские «ёлочки».
- Никаких trailing commas.
- Никаких комментариев внутри JSON.

Язык — русский.
